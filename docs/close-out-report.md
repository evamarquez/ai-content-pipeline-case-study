# Close-out report

## Outcome

The project moved production from roughly two days per article to minutes plus editor review. It produced 549 articles across 882 jobs and reduced the measured failure range to approximately 4-8%.

## What changed

- Repetitive coordination became a visible staged workflow.
- Failures became diagnosable instead of silent.
- Brand context became structured and stage-specific.
- Editors received a reviewable Google Doc with human approval preserved.

## Lessons

1. Design the operating model before optimising individual prompts.
2. Treat failure data as part of the product.
3. Separate production speed from quality and business-impact claims.
4. Do not present built-but-unwired features as production capabilities.
5. Document gaps and recovery context for the next operator.

## Handoff

The team received operating tutorials, screenshots, SOPs, and a record of known implementation gaps. The public version intentionally omits credentials, client data, internal URLs, and production identifiers.
